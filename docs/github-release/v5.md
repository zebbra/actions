# `github-release/v5` - GitHub release (stable semver tags by default)

Create a GitHub Release for eligible tags (stable semver by default; optionally include beta tags).

## Quick usage
```yaml
jobs:
  example:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: zebbra/actions/github-release@github-release/v5
      # with:
      #   <input_name>: <value>
```

## Inputs
| Name | Required | Default | Description |
| ---- | -------- | ------- | ----------- |
| `release_beta_tags` | false | `false` | When `true`, also create releases for tags matching `vMAJOR.MINOR.PATCH-beta.N`. When `false` (default), only stable tags matching `vMAJOR.MINOR.PATCH` are released. |

## Outputs
| Name | Description |
| ---- | ----------- |
| `should_release` | Whether the action created (or will create) a GitHub Release for the current ref. |
| `prerelease` | Whether the release is marked as prerelease (only true for allowed beta tags). |
| `tag` | The tag that was considered eligible for release. |

## What it does

This action creates a GitHub Release for the current ref **only if** the ref name is an eligible tag.

## Tag eligibility

- Stable tags (default): `vMAJOR.MINOR.PATCH` (example: `v1.0.0`)
- Beta tags (optional): `vMAJOR.MINOR.PATCH-beta.N` (example: `v1.0.0-beta.1`)

By default, beta tags are skipped. If `release_beta_tags` is enabled, beta tags are released and marked as prereleases.

## Non-matching refs

If the current `GITHUB_REF_NAME` is not an eligible tag, the action **does nothing and exits successfully** (with a short info log explaining why).
